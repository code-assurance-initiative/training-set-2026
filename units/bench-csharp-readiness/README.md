# ParcelTracking

ParcelTracking keeps merchants informed about their parcels. Merchants register shipments through an HTTP API; a
background worker polls the carriers for new scans, normalises each carrier's status codes, records the tracking
history in PostgreSQL and notifies the merchant of every status change through a signed webhook. Merchants can read a
parcel's history, download its shipping label, redirect it to a pickup point and read delivery-performance figures.

## Projects

| Project | What it is |
|---|---|
| `src/ParcelTracking.Api` | ASP.NET Core API (JWT bearer authentication, one OAuth scope per policy) |
| `src/ParcelTracking.Worker` | background host: carrier polling and merchant webhook delivery |
| `src/ParcelTracking.Core` | parcels, status rules, carrier status normalisation, the tracking service |
| `src/ParcelTracking.Infrastructure` | EF Core persistence and migrations, carrier and webhook HTTP clients, health checks |
| `src/ParcelTracking.Client` | the .NET client library published for merchants (NuGet) |
| `src/ParcelTracking.Cli` | `parcel-admin`, an operator tool that checks carrier status-mapping files |
| `benchmarks/ParcelTracking.Benchmarks` | BenchmarkDotNet benchmarks for the status-normalisation hot path |

## Build and run

Requires the .NET 10 SDK (`global.json`) and a PostgreSQL 16 database.

```sh
dotnet tool restore
dotnet build ParcelTracking.slnx
export ConnectionStrings__Tracking="Host=localhost;Database=parcel_tracking;Username=parcel_tracking"
dotnet ef database update --project src/ParcelTracking.Infrastructure
dotnet run --project src/ParcelTracking.Api
```

The API needs `Authentication:Authority` (an https OpenID Connect issuer) and `CarrierApi:ApiKey`; the worker also
needs `MerchantWebhooks:SigningKey`. Supply them through environment variables or user secrets, never in
`appsettings*.json`.

Telemetry is exported over OTLP when `OTEL_EXPORTER_OTLP_ENDPOINT` is set.

## Testing

```sh
dotnet test ParcelTracking.slnx
```

Unit tests (`tests/ParcelTracking.UnitTests`) cover the domain rules, status normalisation, both HTTP clients
(against in-process stub handlers), the client library, the CLI and the worker's background services. Integration
tests (`tests/ParcelTracking.IntegrationTests`) host the real API with `WebApplicationFactory` over an in-memory
SQLite database, an in-process token issuer and a fake carrier; no test touches the network.
